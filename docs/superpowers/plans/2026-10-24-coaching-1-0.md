# Coaching 1.0 Implementation Plan

> For agentic workers: use superpowers:executing-plans for native implementation, then a fresh review before commit.

**Goal:** Add a safe, lightweight coaching record workflow and show coaching records in the cleaner's paginated control history.

**Architecture:** Store coaching in the existing legacy-compatible coachings table, with model accessors mapping the old schema to cleaner/date/description concepts. Reuse a single SQL UNION timeline query for the cleaner's own history and the administrator's per-employee history; hydrate only items on the requested page. Keep Livewire pages and existing role checks, with no new service dependencies.

**Tech Stack:** Laravel 12, Livewire 4 Volt, SQLite, Tailwind CSS 4, Pest 4.

**Spec:** docs/superpowers/specs/2026-10-24-coaching-1-0-design.md

## Global Constraints
- Keep the verified legacy coachings columns, defaults, and foreign-key behavior; create the table only when absent.
- Do not import or update historical records; do not change production, Classic/Focus scoring, Telegram, or existing request workflows.
- Keep all feature tests on isolated SQLite :memory: connections.
- Preserve auth + approved middleware, server-side authorization, current control result routes, and the conducted-controls profile tab.

## Review Focus
- An inactive or non-cleaner user ID submitted to create is rejected and never changes author identity.
- A cleaner changing a coaching ID in a URL cannot view another cleaner's record.
- A supervisor cannot view another supervisor's private coaching list unless admin.
- Controls and coachings sharing a date have deterministic order across page boundaries.
- Existing legacy columns/data remain unchanged if the migration sees coachings already present.
