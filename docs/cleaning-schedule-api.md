# API назначений уборок для TRIS Academy

Академия запрашивает из внешней системы назначения на текущего сотрудника и рабочую дату. Провайдеру расписания нужно подтвердить этот контракт и сопоставление идентификаторов перед подключением. Реальный адрес и токен задаются на сервере в `CLEANING_SCHEDULE_URL` и `CLEANING_SCHEDULE_TOKEN`.

Ожидается HTTPS GET с `Authorization: Bearer <token>` и параметрами `employee_id`, `date` (`YYYY-MM-DD`), `timezone` (`Europe/Rome`). `employee_id` — ID пользователя Академии. Внешняя система должна хранить соответствие между своим сотрудником и этим ID. `apartment_code` — существующий уникальный код активной квартиры в Академии. Время передаётся с секундами и смещением от UTC. Ответ содержит до 100 назначений за день и использует стабильные уникальные строковые ID.

```json
{
  "date": "2026-11-15",
  "timezone": "Europe/Rome",
  "assignments": [
    {
      "id": "example-1",
      "employee_id": 42,
      "apartment_code": "A-01",
      "starts_at": "2026-11-15T10:30:00+01:00",
      "status": "scheduled"
    }
  ]
}
```

Академия показывает `scheduled` за указанную дату. `cancelled` пропускается. Карточка квартиры доступна по действующей политике доступа. Если карточка недоступна или код совпадает с несколькими активными квартирами, видно только время назначения. Пустой список означает, что уборок сегодня нет. Незаданный источник, таймаут, ошибка HTTP или невалидный ответ дают состояние «Расписание сейчас недоступно».

Назначения обновляются при открытии главной. Интеграция читает расписание и не отправляет изменения провайдеру. Проверка в `HomeRoadmapTest` использует тестовые ответы, поэтому подключение к реальному источнику требует тестового URL и подтверждения формата от его владельца.
