# Emergency TRIS

Emergency TRIS is a read-mostly, static survival package. It is generated by the healthy Laravel application and can be served from a separate static host without Laravel, PHP, or the primary database at request time.

## Content and safety

The snapshot reuses `Instruction` and `InstructionCategory`. An instruction is exported only when it is published, public, has a publication date, belongs to an active category (or has no category), and an editor explicitly enables **Разрешена для Emergency TRIS**. That flag is off by default. Review the full instruction before enabling it. A likely password, token, access/guest/lock code, email, or phone number blocks the whole build instead of being exported. Images and video blocks, apartment-specific KB content, attachments, Telegram data, OI, author details, and model/database identifiers are not exported. Rich text is converted to plain text and static rendering uses text nodes.

## Normal flow

TRIS instructions → allowlisted JSON snapshot → versioned static bundle → configured Emergency TRIS filesystem disk.

Each bundle contains `index.html`, `snapshot.json`, and local CSS/JavaScript under `assets/`. The page renders the snapshot embedded in the HTML, so it has no primary-origin runtime request and can be opened locally. Publishing uploads a versioned release first, then replaces the stable root `index.html` pointer last. A failed build leaves the previous `latest.json` pointer intact; a failed publish leaves the previous remote pointer intact. Incomplete release files may remain unused on the target.

The page displays the build timestamp and warns when the snapshot is older than the configured freshness thresholds. Stale instructions remain visible.

## Feedback

The one universal form supports type (`problem`, `question`, `change`, `completed`, `help`, `other`), area, urgency (`normal`, `important`, `urgent`), optional district/apartment, optional employee name/contact/reference, and required details. Values are configured in `config/emergency.php`.

When configured, the browser sends JSON to the independent HTTPS endpoint:

```json
{
  "submission_id": "uuid",
  "submitted_at": "ISO-8601",
  "snapshot_id": "emergency-version",
  "type": "problem",
  "area": "access",
  "urgency": "important",
  "district": "optional text",
  "apartment": "optional text",
  "name": "optional text",
  "reference": "optional text",
  "message": "required details"
}
```

The endpoint must support browser CORS for the Emergency TRIS origin and accept unauthenticated public submissions without putting credentials in the URL or bundle. A successful HTTP response means only that the endpoint confirmed receipt. If no endpoint is configured or delivery cannot be confirmed, the page retains the draft in browser `localStorage`, offers a copyable JSON report, and explicitly says the report was not sent. The existing TRIS staff feedback path depends on the primary application/Telegram flow, so it is not used as an outage backend.

## Configuration

Set these on the healthy TRIS application; never put secrets in the generated snapshot:

- `EMERGENCY_BUILD_PATH` — local build root; defaults to `storage/app/emergency`.
- `EMERGENCY_FILESYSTEM_DISK` — configured Laravel filesystem disk for publishing. Leave empty to disable publishing and automatic refresh.
- `EMERGENCY_FILESYSTEM_PREFIX` — optional path prefix on that disk.
- `EMERGENCY_FEEDBACK_ENDPOINT` — optional public HTTPS endpoint; no query string, credentials, or primary `APP_URL` origin.
- `EMERGENCY_STALE_WARNING_HOURS` — warning age; defaults to 12.
- `EMERGENCY_STALE_CRITICAL_HOURS` — stronger warning age; defaults to 48.

The project defines local, public, and S3 disks. The S3 Flysystem adapter is not installed in the current checkout, so a configured S3 target is not usable until the compatible adapter and external bucket/static hosting are deliberately provisioned. A local disk is useful for preview but does not survive loss of the primary host.

## Commands and preview

```powershell
php artisan emergency:build
php artisan emergency:publish
php artisan emergency:status
```

`emergency:publish` always builds before uploading. Build output is a versioned directory beneath the configured build root; open that release's `index.html` directly in a browser for a local static preview. No development server is required.

When a usable publication disk is configured, Laravel schedules `emergency:publish` every five minutes with overlap protection. With no valid disk configured, no automatic publish event is registered. Build/publish errors are logged and do not participate in primary request handling.

## Health and outage flow

The existing lightweight Laravel health URL is `/up`. Emergency TRIS does not add a heavy diagnostic endpoint or DNS automation.

Outage flow: staff open the separately hosted Emergency TRIS URL, review the latest snapshot timestamp, use saved instructions, and submit through the independent feedback endpoint when available. Otherwise they copy the retained report for manual delivery.

## Still required before full-host-outage readiness

1. Choose and configure storage independent of the primary host, install its Laravel adapter if needed, and confirm public static reads without exposing write credentials.
2. Configure an external static host/CDN and a staff-known Emergency TRIS URL; validate one non-production build and publish.
3. Provision an independent feedback receiver with storage/retention, CORS, abuse controls, and a human review path; none is currently present in the repository.
4. Configure external health monitoring for `/up` and separately plan DNS/proxy failover. DNS switching is intentionally not implemented here.
5. Select and review the specific instructions allowed for external emergency publication.

Emergency TRIS intentionally contains no apartment-management data, access credentials, employee directory, Telegram messages, OI ledger, internal logs, second operational database, or synchronization workflow.
