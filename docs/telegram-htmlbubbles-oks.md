# ОКС HTMLBubble: контролируемый тест

Эта интеграция — выключенный по умолчанию эксперимент. Она не читает графики уборок, не определяет дежурных, не создаёт контрольные ответы и не обращается к рабочим контролям.

## Доступные данные

В текущей Академии нет подтверждённого источника назначений дежурных по районам и количества уборок на смену. Поэтому карточка явно показывает «Нет подтверждённых данных», а кнопка доступа сообщает, что полномочия нельзя подтвердить без реестра дежурств. Она не делает вывод только по роли пользователя.

Тестовое состояние сообщения хранится в cache до 24 часов, отдельно для пары чат/сообщение. Никакие сведения о реальных контролях там не записываются. Действие «Обновить тестовый статус» доступно только активному одобренному администратору и редактирует `chat_data` того же сообщения.

## Требуемые настройки

В отдельном тестовом окружении задайте:

```dotenv
TELEGRAM_HTMLBUBBLES_ENABLED=true
TELEGRAM_HTMLBUBBLES_TEST_CHAT_ID=-1000000000000
TELEGRAM_HTMLBUBBLES_TEST_THREAD_ID=
```

Укажите новый изолированный тестовый чат. Если нужен форумный топик, задайте только его тестовый `message_thread_id`; протокол WidgetSandbox не подтверждает поддержку этого параметра для экспериментального метода. Отправка будет заблокирована, если тестовый чат совпадает с любым известным в конфигурации рабочим чатом/маршрутом. Настройки токена Work Bot остаются прежними и не выводятся командой.

## Ручной тест

1. Убедитесь, что Work Bot состоит в отдельном тестовом чате и имеет право отправлять медиа.
2. На тестовом окружении включите флаг и задайте отдельный chat ID. Не используйте рабочие чаты, включая дежурную тему.
3. Если настроен тестовый топик, передайте тот же ID; в противном случае не передавайте параметр:

   ```sh
   php artisan telegram:htmlbubbles:send-test --chat-id=-1000000000000
   ```

   ```sh
   php artisan telegram:htmlbubbles:send-test --chat-id=-1000000000000 --message-thread-id=123
   ```

4. Используйте уже существующий Work Bot polling в этом же окружении, не запускайте второй poller. Проверьте обе кнопки: доступ должен остаться неподтверждённым без реестра назначений; обновление тестового статуса должно заменить данные исходной карточки, не создавать новое сообщение и быть доступным только администратору Академии.
5. Если отправка вернулась с неопределённым результатом, сначала проверьте тестовый чат и не запускайте команду повторно вслепую.
6. После теста выключите флаг и удалите только тестовые настройки окружения по принятой процедуре.

У команды нет автоматического fallback на обычный `sendMessage`; отказ beta-метода не приводит к созданию второго текста/сообщения. Существующий Work poller пробует beta только когда флаг включён и тестовый chat ID безопасно настроен. При отказе beta попытка завершается без подтверждения offset: стабильный API не знает `widget_query`, и фильтрация с последующим offset могла бы потерять запрос. Обычный Work polling остаётся без изменений при выключенном флаге или невалидной/неуказанной тестовой цели. Если тестовый beta вызов не работает, выключите флаг, чтобы вернуть обычный стабильный маршрут; неподтверждённые обновления останутся в очереди Telegram.

## Ограничения приёмки

- Стабильная публичная документация Bot API не описывает `sendWidget`, `answerWidgetQuery`, `editMessageWidgetData` или update `widget_query`; их описывает WidgetSandbox как экспериментальный Bot API 10.4 beta.
- Реальный доступ этого Work Bot к beta и фактическая доставка widget updates не подтверждались: для этого нужны отдельный тестовый чат и разрешённое ручное сообщение.
- Поддержка `message_thread_id` в протоколе WidgetSandbox не указана; тест топика требует отдельной проверки.
- Старые/несовместимые клиенты получают текст подписи сообщения вместо HTMLBubble.
