# База знаний по квартирам

Модуль расширяет существующую модель `Apartment`: в ней хранятся общие сведения, а отдельные текстовые разделы и приватные вложения — в связанных таблицах. Telegram Desktop импорт реализован в `TelegramApartmentImportService` и действии Filament «Импорт из Telegram» на странице квартиры. AI-наполнение не используется.

## Доступ

Доступ сотрудников хранится явно в `apartment_user_access`. Запись содержит квартиру, сотрудника, выдавшего доступ и необязательный срок действия. Пара `apartment_id + user_id` уникальна, поэтому повторная выдача обновляет срок, а не создаёт дубль.

- администратор или пользователь с существующим глобальным доступом к admin-панели видит все квартиры, включая черновики и архив;
- обычный сотрудник видит только активные опубликованные квартиры, для которых есть действующая запись `ApartmentUserAccess`;
- `expires_at = null` означает бессрочный доступ;
- истёкший доступ не даёт доступ к списку, карточке и вложениям;
- старые связи `control_responses` намеренно не используются и не импортируются автоматически.

Управление доступами доступно в существующем Filament-ресурсе квартиры: можно выдать доступ одному или нескольким сотрудникам, изменить срок и отозвать доступ. Удаление квартиры не каскадно удаляет записи доступа: внешнее ограничение защищает от случайного удаления истории, пока доступы не отозваны.

## Статус информации

`information_status` разделяет черновик, опубликованную и архивную информацию. Это не заменяет `apartments.is_active`: активность объекта и публикация справочника проверяются независимо.

## Разделы и файлы

Разделы имеют тип, заголовок, текст, порядок, видимость и авторов изменений. Пользовательский вывод экранирует текст и не исполняет HTML. Файлы JPEG, PNG, WebP и PDF хранятся на приватном `local`-диске и выдаются только через авторизованный маршрут с проверкой принадлежности к квартире.

## Пакетный локальный импорт

Команда `apartments:telegram-import` переиспользует существующий импортёр. Новые таблицы, фоновые задачи и обращения к Telegram не нужны. Команда разрешена только в окружении `local` или `testing`. Перед фактическим запуском отдельно проверьте, что основное подключение действительно локальное, и сохраните согласованную резервную копию основной БД и приватного хранилища. Analytics не используется.

Подготовьте JSON-массив связей (manifest). Пути к файлам могут быть абсолютными либо относительно manifest:

```json
[
  {"json": "flat-a/result.json", "media": "flat-a/media.zip", "apartment_id": 123},
  {"json": "flat-b/result.json", "media": "flat-b/media.zip", "name": "Подтверждённое название", "address": "Подтверждённый полный адрес"}
]
```

Примеры условные: замените ID, названия и адреса реальными проверенными значениями. `media` можно опустить только для экспорта без вложений. ZIP должен сохранять относительные пути файлов из JSON. Поддержаны существующие форматы JPEG, PNG, WebP, PDF; видео пока не поддерживается. Экспорт с отсутствующими или неподдерживаемыми вложениями блокируется, чтобы не представить неполный перенос как успешный.

```sh
php artisan apartments:telegram-import /absolute/path/manifest.json --dry-run
php artisan apartments:telegram-import /absolute/path/manifest.json --apply --actor=123
```

`--actor` — существующий одобренный администратор или пользователь с действующим правом управления квартирами. Без `--apply` выполняется только предпросмотр. Вывод — JSON с итоговыми количествами и результатом каждой строки; его можно сохранить перенаправлением в приватный локальный файл.

- `new`: создать неактивную квартиру с информацией в статусе draft.
- `update`: добавить скрытый черновой раздел и приватные вложения существующей квартире. Название, адрес, код, заметки, публикация и доступы не меняются. Существующие model hooks обновляют метаданные времени изменения информации.
- `matched`: этот файл уже импортирован в эту квартиру; ничего не записывать.
- `ambiguous`: несколько квартир по адресу, нужен явный `apartment_id`.
- `error`: неверные данные, отсутствующее медиа, конфликт связи или потенциально перекрывающийся экспорт. Любая ошибка/неоднозначность блокирует весь пакет до начала записи.

Сопоставление адресов строгое: нормализуются только регистр и пробелы. Номер квартиры/корпус должен присутствовать в подтверждённом адресе; одинаковый адрес нескольких объектов требует явного ID. Название чата и свободный текст не считаются доказательством адреса. Один файл должен содержать один чат (`messages`); общий `chats.list` и чат сразу о нескольких квартирах сначала необходимо разделить и вручную сопоставить. Из переписки извлекаются текст, подписи и поддерживаемые файлы без придумывания структурированных полей.

Повтор идентичного файла защищён существующей уникальной парой `apartment_id + sha256`. Повтор квартиры/файла внутри пакета запрещён. Изменённый экспорт уже импортированной квартиры блокируется: дедупликация пересекающихся сообщений между разными файлами пока не реализована. Это требует ручной сверки, а не автоматического повторного добавления истории.

Пакетные процессы защищены общим cache lock; используйте одно локальное окружение с общим cache store. Не выполняйте одновременно ручной импорт Filament или редактирование квартир. Каждая квартира фиксируется отдельной транзакцией; при системной ошибке предыдущие завершённые квартиры сохраняются и пропускаются при повторе. Файловая система не транзакционна: после аварии БД возможны приватные файлы без записей, автоматического удаления нет. Перед повтором проверьте отчёт. Аварийно оставшийся lock истекает через 24 часа.

Большие ZIP существующий импортёр читает в память; разбивайте перенос по квартирам и сначала проверяйте крупнейший реальный экспорт. На данном этапе проверены синтетические экспорты, а не завтрашний набор данных.

## Что подготовить для переноса

1. Отдельные Telegram Desktop JSON и реально выгруженные медиа (не placeholders).
2. Проверенный список соответствий экспортов существующим ID или полным адресам новых квартир.
3. Решения по неоднозначным адресам и пересекающимся экспортам.
4. Локальный пользователь с правом управления, резервная копия БД/файлов и достаточно диска/памяти.
5. Ручная проверка скрытых разделов перед публикацией и выдачей доступов.

Перед возможным Telegram-импортом нужно сначала создать черновой список связей и подтвердить его администратором. Автоматически публиковать закрытые инструкции или подменять ручные доступы импортом нельзя.
