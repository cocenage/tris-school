# TRIS Academy — визуальная система

Статус: проект системы дизайна, подготовленный по аудиту локального кода. Это описание не меняет рабочие страницы, бизнес-логику, Livewire-состояния, маршруты или интеграции.

## 1. Область и принципы

Система предназначена прежде всего для пользовательской части TRIS Academy в мобильном shell шириной до 768 px. Административные панели Filament сохраняют свою функциональность и могут постепенно подключить те же семантические цвета, но не должны смешиваться с мобильной навигацией.

Принципы:

- mobile-first: интерфейс должен быть удобен на телефоне и не ломаться на широком экране;
- спокойная нейтральная поверхность, один основной акцент и понятные семантические состояния;
- визуальная иерархия важнее декоративных эффектов;
- все интерактивные элементы имеют предсказуемые hover, focus, disabled и loading-состояния;
- состояние не передаётся только цветом: используются текст, иконка или форма;
- визуальный рефакторинг не меняет запросы, правила доступа, обработчики Livewire и интеграции.

## 2. Палитра

Новые экраны используют только семантические токены. Значения ниже консолидируют уже встречающиеся в проекте цвета.

| Токен | Значение | Назначение |
|---|---|---|
| `canvas` | `#F4F7FB` | фон приложения вне карточек |
| `surface` | `#FFFFFF` | основная поверхность |
| `surface-muted` | `#F8F8F8` | вторичная карточка, поле, skeleton |
| `border` | `#E7E7E7` | границы и разделители |
| `text` | `#111111` | основной текст |
| `text-muted` | `#6F6F69` | вторичный текст |
| `text-subtle` | `#8A8A84` | подсказки и метаданные |
| `accent` | `#213259` | основной акцент и активное действие |
| `accent-strong` | `#2D6494` | hover, focus и интерактивные ссылки |
| `accent-soft` | `#EEF4FF` | информационный фон |
| `success-bg` / `success-text` | `#EAF7EF` / `#1F7A45` | успешно, подтверждено |
| `warning-bg` / `warning-text` | `#FFF4E5` / `#B76A16` | ожидание, частичное состояние |
| `danger-bg` / `danger-text` | `#FDEDEC` / `#C53B32` | отклонено, ошибка |
| `focus` | `#2D6494` | видимое кольцо клавиатурного фокуса |

Градиент синих оттенков допускается только для основного progress/action-элемента и, при необходимости, для фирменной навигации. Он не должен становиться фоном каждой кнопки или карточки.

## 3. Типографика

Основной шрифт — `Akt`, уже подключённый в `resources/css/app.css`. Запасной стек: `ui-sans-serif, system-ui, sans-serif`.

| Роль | Размер / межстрочный интервал | Начертание |
|---|---|---|
| Display | 24 / 30 px | 600 |
| Page title | 20 / 26 px | 600 |
| Section title | 18 / 24 px | 600 |
| Body emphasis | 16 / 22 px | 500 |
| Body | 15 / 21 px | 400 |
| Body small | 14 / 20 px | 400 |
| Meta / label | 12–13 / 18 px | 500 |

Новые экраны не вводят произвольные размеры между токенами. Длинный текст должен переноситься, а не обрезаться фиксированной высотой.

## 4. Отступы и радиусы

Базовая шкала отступов: `4, 8, 12, 16, 20, 24, 32 px`.

- горизонтальный padding страницы: 16 px на телефоне, 20–24 px на широком экране;
- расстояние между секциями: 20–24 px;
- внутренний padding карточки: 16–20 px;
- расстояние между полем и его ошибкой: 6–8 px.

Радиусы:

- `sm`: 12 px — компактные элементы;
- `control`: 16 px — поля и небольшие кнопки;
- `card`: 24 px — карточки и плитки;
- `sheet`: 28–32 px — модальные окна и bottom sheet;
- `pill`: 9999 px — badge и сегментированные переключатели.

## 5. Кнопки

Базовая высота — 44 px, для важных действий допускается 48 px. Минимальная сенсорная область — 44×44 px.

Семантические варианты:

- `primary` — основное действие, тёмный accent или ограниченный accent-gradient;
- `secondary` — белая/нейтральная кнопка с границей;
- `ghost` — действие без заливки;
- `danger` — разрушительное действие с явным текстом;
- `icon` — только для понятной иконки, обязательно с `aria-label`.

У каждой кнопки должны быть согласованные `focus-visible`, `disabled` и `loading` состояния. Inline-обработчики, меняющие стили вручную, постепенно заменяются классами состояний.

## 6. Формы

Поле состоит из label, control, optional help/error. Высота control — 48–52 px, радиус — `control`, фон — `surface-muted`, граница — `border`.

Ошибку показываем текстом и цветом; placeholder не заменяет label. Select, textarea, загрузка файла и счётчики количества используют те же размеры, focus-ring и отступы.

## 7. Карточки и списки

Карточка имеет одну основную поверхность, ясный заголовок и одинаковый внутренний padding. Визуально важные действия располагаются внизу или справа и не маскируются декоративным фоном.

Списки и табличные данные должны иметь состояния loading, empty, error и populated. На мобильном экране широкая таблица превращается в список карточек или получает безопасный горизонтальный scroll с понятным индикатором.

## 8. Статусы и уведомления

Семантическая карта:

- success: «Подтверждено», «Выдано», «Завершено»;
- warning: «На рассмотрении», «Частично», «Ожидает»;
- danger: «Отклонено», «Отменено», «Ошибка»;
- info: «Черновик», «Назначено», нейтральное пояснение.

`Status badge` всегда содержит короткий текст; точка или иконка — дополнительный, но не единственный сигнал. Toast используется для краткого результата операции, alert — для заметного контекста на странице, empty state — для отсутствия данных.

## 9. Модальные окна, bottom sheet и page header

Используются существующие `x-ui.modal`, `x-ui.bottom-sheet` и `x-ui.toast` как базовые контейнеры. Общие overlay, z-index, close-button, focus и радиусы должны быть определены в одном месте; отдельные страницы не копируют собственные оболочки.

`Page header` содержит back/action, заголовок и необязательные действия поиска или фильтра. Заголовки всех форм должны выглядеть одинаково, независимо от Livewire-обработчика.

## 10. Адаптивность и доступность

- мобильный shell сохраняет safe-area и не полагается на фиксированную высоту контента;
- вложенные `overflow` применяются только к действительно прокручиваемым областям;
- горизонтальные карусели и календарь имеют клавиатурный и touch-доступ;
- focus-visible всегда заметен;
- иконки без текста получают `aria-label`, интерактивные статусы не зависят только от цвета;
- анимация отключается при `prefers-reduced-motion`.

Для Filament ширина, sidebar и таблицы остаются адаптивными по правилам Filament. Общими с пользовательской частью являются только семантическая палитра, типографическая логика и требования доступности.

## 11. Запрещённые визуальные решения

- новый произвольный hex-цвет или радиус без добавления семантического токена;
- inline-style для обычного состояния компонента;
- разные размеры одного и того же типа кнопки или поля на соседних страницах;
- передача статуса только цветом или только точкой;
- icon-only кнопка без доступного имени;
- автоматическая анимация, мешающая чтению или работе с формой;
- копирование оболочки modal/sheet в отдельные Blade-файлы;
- блокировка выделения, печати или контекстного меню для обычного интерфейса без отдельного обоснования безопасности.

## 12. Порядок внедрения

1. Зафиксировать визуальные токены и primitive-компоненты.
2. Привести к ним общий page header, button и поля.
3. Перевести простые статические экраны, затем формы и списки.
4. После пользовательской части отдельно унифицировать тему Filament.
5. На каждом шаге проверять desktop/mobile, keyboard focus, empty/loading/error и не затрагивать бизнес-логику.
