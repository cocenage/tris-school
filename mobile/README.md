# Мобильная Академия — прототип #137

Изолированный Android-проект Capacitor 8 с отдельным package-lock. Laravel, Livewire, серверные права, основной frontend и Telegram-авторизация остаются в существующей Академии.

## Устройство прототипа

Capacitor загружает локальный `dist`. Кнопки открывают существующие страницы Академии через официальный `@capacitor/browser` в системном браузерном представлении. Сайт сохраняет свой мобильный интерфейс и серверную сессию. Удалённая страница не получает Capacitor bridge. В конфигурации нет `server.url`, разрешений удалённой навигации и cleartext.

Этот этап проверяет запуск оболочки и передачу маршрутов. Полноценный встроенный WebView с нативными функциями и автоматический перехват Telegram-ссылок потребуют следующего решения после проверки реального входа. Laravel/Livewire требует работающего сервера, статическая сборка мобильной оболочки его не заменяет.

По умолчанию приложение работает полностью локально. Кнопки показывают проверенный путь в панели проверки. Там нет пользователя, авторизации, рабочих данных и имитации результата контроля. Доступ к серверу включается для каждой сессии чекбоксом, только если при сборке задан HTTPS origin. Это настройка сборщика, пользователь не может вводить произвольный сервер.

## Запуск локальной проверки

Нужен Node.js 22+.

```sh
cd mobile
npm ci
npm test
npm run build
npm run dev
```

Открыть локальный адрес Vite. Нажать «Focus Control», проверить `/checks/control/focus`. Ввести `/profile/checks/42`, проверить путь результата. Ввести `https://other.example/home`, получить отказ. При пустой конфигурации чекбокс доступа к серверу отключён, сетевые обращения к Академии отсутствуют.

## Android

Нужны Android Studio 2025.2.1+, JDK из Android Studio, Android SDK 36, platform-tools и телефон с USB debugging либо эмулятор. Минимальный Android API 24 задан официальным шаблоном Capacitor 8.

```sh
cd mobile
npm ci
npm run android:sync
npm run android:open
```

В Android Studio выбрать телефон и Run. Для командной строки с настроенным SDK выполнить из `mobile/android`.

```sh
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

На Windows использовать `gradlew.bat assembleDebug`. В этой среде Android-проект уже создан и синхронизирован, повторный `cap add android` не нужен.

## Подключение тестовой Академии

Настроить собственный HTTPS тестовый сервер с разрешённым Telegram Login Widget доменом, тестовыми пользователями и существующим серверным приложением. Значение попадёт в публичный bundle. Секреты и токены сюда не передаются.

POSIX shell, из `mobile`.

```sh
VITE_ACADEMY_ORIGIN=https://academy-test.example.org npm run android:sync
```

PowerShell.

```powershell
$env:VITE_ACADEMY_ORIGIN = 'https://academy-test.example.org'
npm run android:sync
```

В приложении включить «Открывать настроенную Академию». Нажать «Главная» и пройти настоящий Telegram Login Widget в браузерном окне. Подпись Telegram проверяет существующий сервер. Mini App `initData` оболочка не генерирует. Если сервер отправит после входа на главную, закрыть браузерное представление и повторно открыть нужный раздел.

Разрешены только точные пути оболочки, `/applications/weekend`, `/applications/vacation`, `/applications/inventory`, `/profile/applications`, `/login`, числовые `/profile/checks/{id}` и `/apartments/{id}`. Вставленные ссылки с другим origin, учётными данными, query/hash, административными и callback-путями отклоняются. Внутри системного браузера работают обычные переходы сайта, включая Telegram. Существующие ссылки из Telegram продолжают открываться обычным способом. Android App Links в прототипе не зарегистрированы.

## Проверено в Linux

- `npm test` — 7 тестов, маршруты, фильтрация URL и граница native bridge.
- `npm run build` — Vite сборка готова.
- `npx cap add android`, `npx cap sync android` — успешная генерация и синхронизация Android с Browser plugin.
- `./gradlew assembleDebug --no-daemon` — сборка остановилась при загрузке Gradle 8.14.3 с `Network is unreachable`. Android SDK и adb в среде отсутствуют. APK не получен.
- Попытка браузерной проверки через Playwright остановилась при запуске Chromium с `socket() failed: Operation not permitted`. Визуальная проверка не выполнена.

Приёмка на телефоне, вход через реальный Telegram и сценарии с рабочими данными остаются открытыми. Серверы Академии, аккаунты, Telegram API и production-данные при разработке не использовались. Миграции, отправки и деплой не выполнялись.
